## 2. Implemented

Реально реализованные части MVP (проверено по коду):

### Foundation
- React + TypeScript + Vite сборка.
- `AppShell` — общий responsive layout (mobile-first).
- Клиентская навигация через локальное состояние в `App.tsx` (экраны: landing, creation-start, story, period).
- Типизированные данные: `MemoryCardData`, `PeriodData`, `StoryStructure` (`src/types/index.ts`).
- Mock-данные истории (`src/data/mockStory.ts`).
- Общие CSS-переменные и глобальные стили (Warm Editorial / Human Memory).

### Visual layer
- Warm Editorial / Human Memory визуальный стиль: тёплый paper/ivory фон, спокойная палитра, editorial типографика, мягкие тени, умеренные радиусы.
- Responsive сетка карточек (mobile 2 → desktop 3–4 колонки).
- `prefers-reduced-motion` поддержка.
- `StoryHeader` — минимальный editorial header (default / with back / with action).

### Creation flow
- `Landing` — hero c headline и CTA «Создать свою историю».
- `CreationStart` — выбор стартового периода из предзаданных (с пометкой «С чего начать»), переход к периоду.
- `StoryScreen` — главный экран «Моя история», список периодов с карточками.
- `PeriodScreen` — экран периода со switcher между периодами, сеткой карточек и ссылкой «Моя история».
- `PeriodSection` — секция периода с сеткой карточек.
- `AddMemoryCard` — добавление карточки «＋ Добавить своё».
- Сортировка: заполненные карточки идут до пустых в сетке периода.

### Memory editing
- `MemorySheet` — bottom sheet (mobile) / центрированная панель (desktop) для редактирования карточки.
- Поля: название (≤30), год (≤4 цифры), воспоминание (≤150), с placeholder `Хочешь добавить пару слов?`.
- Автосохранение изменений (нет кнопки «Готово» для обычного редактирования) — изменения применяются в состояние карточки через `onChange`.
- Закрытие через кнопку, фон и клавишу Escape.
- Удаление фотографии с подтверждением (включая возврат к вопросу при повторном нажатии).
- Удаление карточки (удаление фото не удаляет карточку само по себе).

### Photo upload
- `PhotoPicker` — нативный выбор одного файла-изображения (`accept="image/*"`), только один файл.
- `createObjectUrl` / `releaseObjectUrl` (`src/utils/photo.ts`) — управление object URLs.
- Большой полупрозрачный `+` в фото-области пустой карточки (не стандартная кнопка «Добавить фото»).
- Замена существующей фотографии из MemorySheet.

### Photo cropper
- `PhotoCropper` — экран кадрирования с фиксированной рамкой 4:5.
- Drag/pan фотографии, zoom (кнопки и wheel).
- Пользователю не показывается выбор соотношения сторон (рамка задаётся компонентом).
- Сохранение crop через canvas → JPEG data URL → фото сразу появляется в карточке.
- Масштабирование вывода по density (dpr, cap 2).
- Поддержка кнопки закрытия и клавиши Escape.
- CSS-fix stage `width: fit-content` + img `max-height: 64vh` (разрешение диагностики stage=0x0) — применён.

## 3. Current UX

Фактически реализованный пользовательский путь:

1. **Landing** (`Landing`) — headline + CTA «Создать свою историю».
2. **Начало создания** (`CreationStart`) — выбор периода, с которого начать («С чего начать» у «Детство»).
3. **Первый период** (`PeriodScreen`) — экран выбранного периода с сеткой карточек.
4. **Карточки и фото:** на экране периода можно открыть карточку для редактирования (`MemorySheet`), добавить новую карточку (`AddMemoryCard`), добавить фото через `+` (`PhotoPicker` → `PhotoCropper` → фото в карточке).
5. **Главный экран «Моя история»** (`StoryScreen`) — итоговый список периодов и карточек; возврат из периода.

Не реализовано (не описывать как готовое): прогрессивный guided-сценарий «предложение карточки → добавление фото → crop → данные → следующая рекомендация», wow-момент, viewer готовой истории, уровни атмосферы.

## 4. Product constraints

Важные ограничения MVP, которые нельзя случайно нарушить:

- Одна фотография ровно на одну карточку.
- Видео отсутствует.
- Нет множественной загрузки, галерей, коллажей.
- Выбор соотношения сторон отсутствует — cropper использует фиксированную рамку 4:5, пользователю выбор не показывается.
- Большой полупрозрачный `+` не заменяется стандартной кнопкой «Добавить фото».
- Удаление фото не удаляет карточку.
- Нет backend / persistence / auth — MVP работает на локальном состоянии и mock-данных; данные не сохраняются между сессиями.
- Нет gamification, XP, badges, medals, streak, процентов прогресса.
- Нет dashboard/SaaS/photo-archive логики.
- Нет AI-функций.
- Нет sharing, PDF export, социальных функций.
- Нет кнопки «Готово» для обычного редактирования — изменения сохраняются автоматически.
- Не менять одобренную визуальную концепцию Warm Editorial / Premium Editorial.

- **PhotoDeleteDialog** с выбором «Оставить» / «Удалить всё» (сейчас в MemorySheet есть упрощённое подтверждение удаления фото).

- Создание собственного периода («＋ Добавить свой период») — есть в PRD, входит в MVP, пока не реализован.

### Не входит в MVP / реализуется только по отдельному требованию (по PRD, раздел 19)
- Видео, множественная загрузка/галереи/коллажи, AI-функции, PDF export, sharing, сложная авторизация, социальные функции, achievement/game-механики.

## 6. Known limitations

Только подтверждённые по коду:

- **Нет персистентности:** состояние истории живёт в React-состоянии `App.tsx` и сбрасывается при перезагрузке; реальных пользовательских загрузок нет (mock-фото из `/img/*.svg`).
- **Год как текст:** в `MemorySheet` год — числовое поле (≤4 цифр), а не picker/рулетка из спецификации.
- **Подтверждение удаления фото упрощено:** в `MemorySheet` реализовано двухшаговое подтверждение («Точно удалить фотографию?»), но нет разделения «Оставить» / «Удалить всё» из PRD.
- **Пустые карточки перемещаются без анимации:** заполненные идут раньше пустых, но плавный transition переупорядочивания не реализован.
- **MemorySheet — центрированная панель и на desktop/mobile** (через CSS), без раздельной спецификации поведения bottom sheet vs modal на уровне компонента.
- **type `PeriodData` объявлен дважды** в `src/types/index.ts` — дублирование определения (технический долг).
- **Файл может расходиться с кодом** — не менять функциональный код, если только не требуется задача.
